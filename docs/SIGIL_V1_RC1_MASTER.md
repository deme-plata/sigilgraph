## 1. TURBOSYNC-X — the design (target of Terminal B)

New nodes must **verify chapters, not read the whole novel page-by-page.** Layered on top of existing `block_sync`, never a rewrite.

| Layer | What | Lands in |
|---|---|---|
| **Tip Certificate** | signed `{height, hash, 4 roots, producer, quorum}` — light clients trust the proof, not the server | `flux-turbo-sync` + `sigil-rpc` |
| **Epoch Segment Manifests** | every 16,384 blocks: range, first/last hash, parent boundary, BLAKE3 rolling root, header-merkle root, state roots, codec, chunk CIDs | `flux-turbo-sync` (Wave 2) |
| **CAS chunk store** | chunks fetched by content-hash from peers / HTTP cache / local / CDN — fastest source wins | reuse `flux-sync` BlockStore ([[project_flux_sync_backfill]]) |
| **FEC shards** | k-of-n erasure shards from multiple peers → one slow/missing peer can't stall sync | `flux-turbo-sync` |
| **Bitmap gap sync** | client asks "which segments/chunks am I missing?" instead of chasing heights | `sigil-chronos::backfill` extend |
| **Hot snapshot lane** | snap to `tip − N`, verify state root, go live in seconds, backfill history in background | `sigil-top` sync path |
| **Range witnesses** | skiplist/Merkle proofs for segment boundaries → verify big ranges fast, lazy-verify deeper | `flux-turbo-sync` |

**Honest claim:** 50× is realistic for **time-to-live/synced-enough** (snapshot + manifests + CAS/FEC), NOT for full archival replay from genesis (still I/O-bound). Say this in the release notes — no overclaim.

**Acceptance gate (chronos, deterministic):** `flux_sigil_chronos_ci` / sigil-chronos scenario must show **`blocks_applied=N, divergence=0`** for: (a) hot-snapshot join, (b) one slow peer, (c) one missing chunk recovered via FEC, (d) tamper-reject on a bad manifest. No gate = not shipped.
