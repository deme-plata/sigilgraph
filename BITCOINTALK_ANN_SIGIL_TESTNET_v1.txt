[b][size=13pt]Why SIGIL[/size][/b]

Money is the one thing we're least allowed to get wrong and the one we most take on faith — discretionary supply, settlement through intermediaries, a ledger we're shown instead of one we can check. Bitcoin proved the last part isn't a law of nature. But the chains built on that insight each stopped short:

[list]
[*][b]Bitcoin[/b] established capped, independently verifiable money, but deliberately limits general-purpose programmability; its header commits transactions rather than a dedicated state root, and secp256k1 is not post-quantum.
[*][b]Ethereum[/b] established general-purpose programmable state and already commits state, transaction and receipt roots in every execution header — but it does not provide a fixed 21M monetary policy, a post-quantum signature floor, or protocol-level provenance for released client binaries.
[/list]

SIGIL's distinction is the combination neither puts in the protocol: [b]four domain-separated state roots with fail-closed local enforcement[/b] (a node that drifts on any root halts itself before serving a byte), a [b]post-quantum signature floor[/b], [b]protocol-level provenance[/b] binding each released binary to its build, and a [b]time-normalized capped emission[/b]. Keep what Bitcoin and Ethereum got right — capped honest money, programmable state — and add what post-quantum cryptography and a self-signing compiler now make possible.

Here is what that buys you, and it is all live on the testnet today:

[list]
[*]🔐 [b]Every official binary carries verifiable build provenance.[/b] Each release carries a post-quantum proof — require-both [b]SQIsign Level 5 AND Ed25519[/b] over a canonical record binding the artifact hash, source hash, compiler version and builder wallet. ~356 bytes total, smaller than one Dilithium-5 signature (4,595 B); a stripped single-leg bundle is rejected. [b]Honest scope:[/b] this proves a specific key attested that artifact X was built from source Y with compiler Z — it does [i]not[/i] by itself prove the binary was faithfully produced from that source. Reproducible builds (an independent rebuild yielding the identical hash) are the goal and are not yet independently confirmed. You verify the artifact hash + both signatures yourself (walkthrough below).
[*]📦 [b]Four state roots in every header[/b] (wallet / dex / event-log / contract). A node that drifts on any root diverges on the header and [b]halts itself[/b] (exit 78) before it serves a single byte. State divergence has nowhere to hide.
[*]⚙️ [b]A programmable economy, inside the guarantee.[/b] A contract [b]VM[/b], a constant-product [b]AMM DEX[/b] (x·y=k), on-chain [b]credit[/b] (collateralized, experimental), and a [b]Bitcoin bridge[/b] ([b]SPV[/b] — it verifies a Bitcoin SPV proof + PoW finality, not a custodian or federation) — each committing to its own state root, so the whole economy lives under the structural guarantee instead of bolted beside it.
[*]🔎 [b]One constant-size proof for the whole chain.[/b] The fold (Ajtai/SIS lattice commitments, no trusted setup) compresses the chain prefix into [b]2,568 bytes regardless of length[/b]. One check attests the folded chain of per-block commitments back to genesis (header continuity + the committed roots) — [i]not[/i] every transaction, every signature, or the DAG ordering. Full fold verification is 280–342 ms at the 100k-block benchmark. The [b]3-µs tip check is a different, cheaper operation[/b]: it recomputes the exact BLAKE3 tip fingerprint a native node commits and compares it — an incremental check against an already-verified fold state, not a re-verification of the fold itself.
[*]💻 [b]One binary does everything, on a potato.[/b] sigil-top (Linux x86_64 + Windows x64) is a monitoring node, a light client, a dual-lane miner, and a wallet in a single static file. Default mode verifies the live tip fingerprint in ~3 µs with zero blocks downloaded. Opt-in full sync runs at a measured live 10,853 blocks/s.
[*]📡 [b]A measured gossip law, not a guess.[/b] Delivery probability D(p,r) = 1 − p^r, validated against 22 seeded simulations (RMS residual 0.4 pp). The shipped redundancy r=3 clears a 99.9% delivery SLA at up to 10% packet loss — the network calculates its provisioning instead of hoping.
[*]🕸️ [b]Adversarially gated ordering.[/b] The DagKnight braid passed a six-scenario gate before the live producer adopted it: divergence = 0 under 30% drop/reorder/equivocation, a withheld-block attacker, 16/16 ordering permutations agree, tamper suite 5/5 rejected. Simulation evidence, not a theorem — and we label which is which.
[*]₿ [b]Bitcoin-familiar economics.[/b] 21M cap, 4-year halvings — but time-based: block reward = the integral of the emission rate over the block interval, so the schedule is invariant under block cadence, a compile-time assert proves it sums exactly to the cap, and a fail-loud enforcer halts the node at ±2% supply drift.
[/list]

[b][size=13pt]The plan: testnet now, mainnet when it earns it[/size][/b]

We are on testnet [b]on purpose[/b]. The claims above — a post-quantum provenance chain, a constant-size whole-chain proof, structural agreement — are exactly the kind that should be attacked by strangers before anything of value depends on them. So the road to a production mainnet is public and gated on closing a short, named list of hardening items (block-apply producer-signature enforcement, the trustless VDF modulus, peer-sync ingress authentication), each tracked with file:line status in an open backlog. When they close and the chain has soaked, mainnet follows. Until then: break it, and tell us how.

[b][size=13pt]Break it — specific missions[/size][/b]

Concrete things to try, in rough order of effort:

[list]
[*][b]Verify a binary[/b] — recompute the artifact BLAKE3 and check both provenance signatures (walkthrough below). Tell us if a hash or signature doesn't line up.
[*][b]Run a node and compare roots[/b] — sync, then diff your four state roots against a peer's at the same height. Any mismatch that doesn't halt the node is a finding.
[*][b]Corrupt local state and confirm fail-closed[/b] — tamper with your local DB and verify the node refuses to serve (exit 78) instead of propagating.
[*][b]Mine for 30 minutes[/b] on a bound wallet and confirm rewards + the 1.2% commons split land as claimed.
[*][b]Attack peer-sync auth[/b] — the verify-before-sync handshake is in log-only mode; try to feed a follower blocks it should refuse, and tell us what it accepts.
[*][b]Test partition recovery[/b] — split a small local mesh, produce on both sides, rejoin, and report how (or whether) ordering reconciles.
[*][b]Submit fold test vectors[/b] — feed the fold verifier crafted inputs and look for a proof it accepts that it shouldn't.
[/list]

Report findings at the GitHub repo issues (link below). Security-sensitive findings: open a minimal issue and we'll coordinate a private channel.

[b][size=13pt]Mining[/size][/b]

Dual-lane: a hash-power lane (BLAKE3-family PoW) × a verifiable-delay lane (Wesolowski VDF) — a valid share carries both. CPU is fine; a GPU build is available for the hash lane. [b]Ownership-proven wallets[/b] (you sign a domain-separated challenge to bind the wallet — the wallet IS the public key, [i]no KYC[/i]) earn to themselves; unbound mining routes to the treasury. 1.2% of every reward routes to a commons pool under an M-of-N quorum (currently operator-held — see decentralization note above).

[b][size=13pt]What we are NOT claiming[/size][/b]

The honesty section is load-bearing — the whitepaper carries a boxed security disclosure and a public hardening backlog with file:line status. The short version:

[list]
[*]RPC money routes ARE authenticated (per-wallet ed25519 signature + nonce). The residual risk is deeper, and named: block-apply does not yet enforce the producer's signature (verifier written + height-gated, dormant); the live VDF modulus is not yet the trustless one (drop-in built, height-gated cutover pending); peer-sync ingress auth is mid-rollout (a real ed25519 verify-before-sync handshake with channel binding landed in log-only mode). [b]Do not route real value through SIGIL.[/b] It's a testnet; it will be reset.
[*]The multi-million-tx/s figures in our docs are state-transition wind-tunnel numbers, not network TPS, and are labeled as such everywhere.
[*]The fold construction is ours and unpublished; its soundness reduction (Ajtai/SIS) is a target, not a published proof. Cryptanalysis is explicitly invited — that's half the reason this post exists.
[/list]
